## 프로젝트 배경

### 소스 출처

본 보고서는 2026-03-31에 유출된 Claude Code 전체 TypeScript 소스 스냅샷을 기반으로 한다. 해당 스냅샷은 512,664행의 TypeScript 코드(`.ts` + `.tsx`)를 포함하며, 1,884개 파일, 35개 최상위 디렉토리에 분산되어 있다. 소스는 mini 서버 `~/Documents/openclaw/Doramagic/docs/research/claude-code-instructkr/src/`에 저장되어 있다.

### 분석 방법론

**14개 서브에이전트 병렬 분석** 아키텍처를 채택했다. 5개의 Opus 에이전트가 핵심 복잡도가 높은 장(아키텍처 총람, Query Engine, Agent 편성, 보안 모델, 컨텍스트 관리)을 담당하고, 9개의 Sonnet 에이전트가 나머지 장을 담당했다. 각 에이전트는 독립적으로 소스를 읽고, 아키텍처 패턴을 추출하며, 경쟁 제품 분석 결론을 검증했고, 최종적으로 총편집자가 통합 교열했다.

이 방법론 자체가 Claude Code 다중 에이전트 아키텍처(4장)의 실제 검증이다—Claude Code로 Claude Code를 분석했다.

### win4r/cc-notebook과의 비교

win4r/cc-notebook은 같은 소스에 대한 기존 커뮤니티 분석 노트다. 본 보고서는 다음 차원에서 현저한 개선을 달성했다:

- **독립적 도구 시스템 장(3장)**: cc-notebook은 도구 시스템을 별도로 분석하지 않았으며, 본 보고서가 이 핵심 공백을 채웠다
- **소스 수준 검증**: 모든 아키텍처 주장에 파일명, 줄번호, 코드 스니펫이 첨부되어 있으며, 2차 인용이 아니다
- **이론적 근거**: 각 장은 학술 이론 기반(정보이론, 캐시 이론, 인지과학 등)으로 시작하여 공학적 구현을 더 넓은 지식 프레임워크 안에 위치시킨다

## 장별 안내

### 1장: 아키텍처 총람과 시작 흐름
**파일**: [01-architecture-overview.md](01-architecture-overview.md)

**핵심 통찰**: Claude Code는 React/Ink 기반의 터미널 TUI 애플리케이션으로, Bun을 선호 런타임으로 사용하며 REPL 루프를 통해 Claude API를 구동하여 agentic 프로그래밍 작업을 수행한다.

**주요 발견**:
- 기술 스택 선택의 정확성: Bun + TypeScript + React/Ink + Zod v4 + OpenTelemetry, 각 선택에 명확한 공학적 이유가 있다
- 512,664행의 코드가 1,884개 파일, 35개 최상위 디렉토리에 분산된 성숙한 대형 엔지니어링 프로젝트
- 기능 플래그 시스템은 GrowthBook + bun:bundle 이중 트랙을 채택, 컴파일 시점에 내부 기능을 제거

**권장 우선순위**: ★★★★★ — 반드시 읽어야 할 시작점, 전체적인 멘탈 모델 구축

### 2장: Query Engine — LLM 인터랙션 핵심
**파일**: [02-query-engine.md](02-query-engine.md)

**핵심 통찰**: Query Engine은 Claude Code의 "심장 박동"으로, 7,400행의 코드(전체의 1.4%에 불과)로 제품의 가장 핵심적인 경로를 구동한다—사용자와 Claude의 모든 인터랙션이 여기를 반드시 통과한다.

**주요 발견**:
- 핵심 아키텍처는 Async Generator Pipeline(코루틴 파이프라인)으로, 스트리밍 응답, 도구 호출, 컨텍스트 압축, 비용 추적을 하나의 async generator에서 편성
- 최소 12종의 예외 분기 처리: 컨텍스트 윈도우 오버플로, 토큰 예산 소진, API 오류, 사용자 중단, 권한 승인 등
- 토큰 예산과 auto-continue 결정 메커니즘으로 긴 작업이 모델의 stop으로 인해 중단되지 않도록 보장

**권장 우선순위**: ★★★★★ — 제품 전체 작동 방식 이해의 핵심

### 3장: 도구 시스템
**파일**: [03-tool-system.md](03-tool-system.md)

**핵심 통찰**: 도구 시스템은 LLM의 의도와 실제 세계 사이의 유일한 통로—부속품이 아닌 핵심 공학 자산이다.

**주요 발견**:
- 자기 기술 도구(Self-Describing Tools) 패턴: 각 도구는 `searchHint`, `prompt`, `userFacingSchema` 등의 필드를 통해 자신의 능력을 선언하여 모델이 동적으로 선택할 수 있게 한다
- 40+ 개의 도구 서브디렉토리, `toolExecution.ts`(1,745행)가 통합 스케줄링 실행
- cc-notebook이 이 시스템을 별도로 분석하지 않아 본 장이 핵심 공백을 채움

**권장 우선순위**: ★★★★☆ — Agent 개발자 필독

### 4장: Agent 편성과 다중 에이전트 아키텍처
**파일**: [04-agent-orchestration.md](04-agent-orchestration.md)

**핵심 통찰**: 세 가지 점진적 협업 모드(Subagent / Coordinator / Team Mode)가 동일한 `runAgent()` 핵심 엔진을 공유하며, 파라미터 조합을 통해 다른 동작을 구현한다—이것이 가장 우아한 설계 결정 중 하나다.

**주요 발견**:
- 8,700행의 코드, 12개의 핵심 모듈, 전체 제품 아키텍처에서 가장 복잡한 서브시스템
- Team Mode는 파일 메일박스 프로토콜(`teammateMailbox.ts`, 1,183행)을 사용하여 지속적 병렬 협업 구현
- Coordinator Mode는 `<task-notification>` XML을 통해 완전 비동기 통신, 독립적 AbortController 격리 보유

**권장 우선순위**: ★★★★★ — 다중 에이전트 시스템 설계의 교과서적 사례

### 5장: Prompt 엔지니어링
**파일**: [05-prompt-engineering.md](05-prompt-engineering.md)

**핵심 통찰**: Prompt 엔지니어링은 전체 시스템에서 암묵적 복잡도가 가장 높은 서브시스템이다—`systemPromptSection` 3행의 조정이 모델 동작, Cache 적중률, 토큰 과금, 크로스 세션 일관성에 동시에 영향을 미칠 수 있다.

**주요 발견**:
- 8,000+ 토큰의 시스템 프롬프트는 "설명"이 아니라 정밀한 행동 프로그래밍
- Prompt Cache 계층화 전략(`cacheScope: 'org'` / `'global'`)으로 수백만 요청의 토큰 비용을 한 자릿수 낮춤
- `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` 마커가 공유 접두사 경계를 정확히 구분, 글로벌 캐시 적중을 최대화

**권장 우선순위**: ★★★★★ — Prompt 엔지니어 필독, 상업 수준 Prompt 설계의 범례

**주요 발견**:

**권장 우선순위**: ★★★★☆ — Doramagic Skill 설계에 직접적인 참조 가치

### 7장: 명령 시스템
**파일**: [07-command-system.md](07-command-system.md)

**핵심 통찰**: 명령 시스템은 명확한 관심사 분리를 구현한다—명령은 "트리거"를 담당하고, 도구는 "실행"을 담당하며, LLM은 "결정"을 담당한다.

**주요 발견**:
- 세 가지 명령 유형: PromptCommand(LLM 대화에 주입), LocalCommand(로컬 실행), LocalJSXCommand(UI 렌더링 포함)

- 고전 GoF 명령 패턴의 두 가지 핵심 확장: 지연 로딩 + 타입화된 반환값

**권장 우선순위**: ★★☆☆☆ — 일반적인 디자인 패턴 적용, 필요에 따라 읽기

### 8장: 컨텍스트 관리
**파일**: [08-context-management.md](08-context-management.md)

**핵심 통찰**: 컨텍스트 관리는 본질적으로 정보 압축 문제다—Claude Code는 무손실에서 유손실까지의 점진적 강등 체계를 설계하여 200K 토큰 윈도우 내에서 시간 단위의 세션 연속성을 유지한다.

**주요 발견**:

- 안전 불변량: tool_use/tool_result 쌍은 끊을 수 없고, 재귀 보호와 Circuit Breaker 메커니즘 보유

**권장 우선순위**: ★★★★☆ — 장기 세션 Agent 개발의 핵심 참조

### 10장: 보안과 권한 모델

## 용어 사전

| 용어 | 정의 |
|------|------|
| **Agentic Loop** | LLM이 루프에서 "추론→도구 호출→결과 주입→재추론"을 교대로 실행하며 작업이 완료될 때까지 반복. Claude Code의 핵심 실행 모드. |
| **Async Generator Pipeline** | TypeScript의 `async function*` 코루틴. Query Engine이 스트리밍 응답의 점진적 출력을 편성하는 데 사용. |
| **Auto-Continue** | 모델이 토큰 제한으로 인해 멈출 때(`end_turn`이지만 미완료 도구 호출이 있을 때), Query Engine이 자동으로 계속 지시를 주입하여 사용자 경험을 중단시키지 않는 것. |
| **Cache Editing** | Claude API의 캐시 편집 기능으로, 전체 캐시를 무효화하지 않고 이전 메시지의 캐시 복사본을 삭제할 수 있다. 마이크로 압축의 기반. |
| **CLAUDE.md** | 사용자/프로젝트 수준의 지시 파일로, `.editorconfig`와 유사하지만 AI를 위한 것. 시스템 프롬프트에 주입되어 모델 동작을 지도. |
| **Coordinator Mode** | Agent 편성의 두 번째 계층 모드: 완전 비동기 통신, XML 알림을 통해 여러 Agent를 조율하며, 각자 독립적인 AbortController를 보유. |
| **DCE (Dead Code Elimination)** | 컴파일 시점에 도달 불가능한 코드를 제거. bun:bundle의 `feature()` 호출로 내부 기능이 외부 빌드에서 완전히 삭제됨. |
| **Defense in Depth** | 종심방어 전략. Claude Code의 8층 보안 체계: 권한 모드→규칙 매칭→AST 분석→보안 검증기→경로 검증→분류기→Hook→샌드박스. |
| **Fork Agent** | 컨텍스트 전체 압축 시 시작되는 독립 Agent로, 완전한 대화 이력을 읽고 구조화된 요약을 생성하며 현재 세션을 오염시키지 않음. |
| **Frontmatter** | Markdown 파일 헤더의 YAML 메타데이터 블록(`---`으로 감싸짐). Skill 파일이 권한, 모델, 트리거 조건 등을 선언하는 데 사용. |
| **GrowthBook** | 런타임 Feature Flag 플랫폼, A/B 테스트와 점진적 출시 지원. Claude Code가 기능 스위치와 샘플링 비율을 동적으로 제어하는 데 사용. |
| **Ink** | React 기반 터미널 UI 프레임워크. Claude Code가 렌더링 파이프라인을 깊게 개조했다(이중 버퍼, ANSI diff, 하드웨어 스크롤). |
| **MCP (Model Context Protocol)** | Anthropic 주도의 개방형 프로토콜로, AI 애플리케이션과 외부 도구 서비스 간의 표준화된 통신을 정의. JSON-RPC 2.0 기반. |
| **Micro-Compaction (마이크로 압축)** | 컨텍스트 관리의 첫 번째 단계 전략: cache editing을 통해 이전 도구 결과의 서버 측 캐시를 삭제하고, 로컬에는 플레이스홀더를 유지. 무손실. |
| **Overload Fallback** | 주 모델(예: Opus) 과부하 시 보조 모델(예: Sonnet)으로 투명하게 강등하되, 반드시 사용자에게 경고를 표시하며, 절대 조용히 전환하지 않음. |
| **Prompt Cache** | Claude API의 프롬프트 캐시 메커니즘. 동일한 접두사를 가진 요청이 캐시를 공유하여 토큰 비용을 크게 낮춤. `org`와 `global` 두 가지 범위로 분류. |
| **REPL** | Read-Eval-Print Loop, Claude Code의 핵심 인터랙션 모드: 사용자 입력 읽기→LLM 처리→결과 출력→다음 라운드 대기. |
| **Skill** | Markdown 형식의 워크플로 정의로, 슬래시 명령어나 AI의 주동적 호출로 트리거된다. 본질적으로 "AI를 위한 SOP". |
| **Subagent** | Agent 편성의 첫 번째 계층 모드: 주 프로세스 내에서 동기/비동기로 실행되는 하위 Agent, 함수 반환값을 통해 통신. |
| **System Reminder** | 대화 이력에 주입되는 시스템 수준 메시지로, 현재 날짜, 사용 가능한 Skill 목록 등 모델의 컨텍스트 정보를 동적으로 업데이트하는 데 사용. |
| **Team Mode** | Agent 편성의 세 번째 계층 모드: 파일 메일박스 프로토콜을 통해 지속적 병렬 협업을 구현하며, Tmux Pane / InProcess / Remote 3가지 백엔드를 지원. |
| **Tool Result Storage** | 도구 실행 결과의 디스크 콜드 스토리지(`toolResultStorage.ts`). 마이크로 압축 후 도구 결과가 컨텍스트에서 여기로 이동되며, 필요 시 복원. |
| **TUI (Terminal User Interface)** | 터미널 사용자 인터페이스. Claude Code가 순수 텍스트 터미널에서 구현한 인터랙티브 인터페이스로, React/Ink 선언적 렌더링 기반. |
