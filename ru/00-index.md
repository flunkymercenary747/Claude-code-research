# Полный аналитический отчёт об архитектуре Claude Code

> **Базовая версия исходного кода**: снимок TypeScript-исходников Claude Code (31 марта 2026 г., ~512K LOC, ~1 900 файлов)
> **Дата анализа**: 2 апреля 2026 г.
> **Объём отчёта**: 14 глав, 428 КБ

---

## Контекст проекта

### Источник исходного кода

Настоящий отчёт основан на полном снимке TypeScript-исходников Claude Code, ставшем публично известным 31 марта 2026 г. Снимок содержит 512 664 строки TypeScript-кода (файлы `.ts` + `.tsx`), распределённых по 1 884 файлам в 35 каталогах верхнего уровня. Исходный код хранится на сервере mini по пути `~/Documents/openclaw/Doramagic/docs/research/claude-code-instructkr/src/`.

### Методология анализа

Использована архитектура **параллельного анализа с 14 субагентами**: 5 агентов Opus отвечали за главы с наибольшей сложностью (архитектурный обзор, Query Engine, оркестрация агентов, модель безопасности, управление контекстом), 9 агентов Sonnet — за остальные главы. Каждый агент независимо читал исходный код, извлекал архитектурные паттерны и верифицировал выводы сравнительного анализа; финальную редактуру выполнял главный редактор.

Эта методология сама по себе является практической проверкой многоагентной архитектуры Claude Code (Глава 4) — Claude Code анализирует Claude Code.

### Сравнение с win4r/cc-notebook

win4r/cc-notebook — ранее опубликованные заметки сообщества по тому же исходному коду. Настоящий отчёт существенно их дополняет:

- **Отдельная глава о системе инструментов** (Глава 3): cc-notebook не анализировал систему инструментов самостоятельно — настоящий отчёт заполняет этот ключевой пробел
- **Верификация на уровне исходного кода**: каждое архитектурное утверждение подкреплено именем файла, номером строки и фрагментом кода, а не пересказом из вторых рук
- **Теоретическое обоснование**: каждая глава начинается с академических теоретических основ (теория информации, теория кэширования, когнитивные науки и др.), помещая инженерную реализацию в более широкие рамки

## Путеводитель по главам

### Глава 1: Архитектурный обзор и процесс запуска
**Файл**: [01-architecture-overview.md](01-architecture-overview.md)

**Ключевая идея**: Claude Code — это TUI-приложение на основе React/Ink, работающее в терминале, использующее Bun как предпочтительную среду выполнения и управляющее Claude API через цикл REPL для выполнения задач программирования в стиле agentic.

**Ключевые находки**:
- Точный выбор стека: Bun + TypeScript + React/Ink + Zod v4 + OpenTelemetry — у каждого выбора есть чёткое инженерное обоснование
- 512 664 строки кода в 1 884 файлах в 35 каталогах верхнего уровня — зрелый крупный инженерный проект
- Система feature flags использует двойную схему GrowthBook + bun:bundle с отсечением внутренних функций на этапе компиляции

**Рекомендуемый приоритет**: ★★★★★ — обязательное начало для формирования глобальной ментальной модели

---

### Глава 2: Query Engine — ядро взаимодействия с LLM
**Файл**: [02-query-engine.md](02-query-engine.md)

**Ключевая идея**: Query Engine — «сердцебиение» Claude Code: 7 400 строк кода (всего 1,4%) управляют самым критическим путём продукта — каждое взаимодействие пользователя с Claude проходит через него.

**Ключевые находки**:
- Основная архитектура — Async Generator Pipeline (конвейер сопрограмм), который оркестрирует потоковый ответ, вызов инструментов, сжатие контекста и отслеживание стоимости внутри одного async generator
- Обрабатывает минимум 12 ветвей исключений: переполнение окна контекста, исчерпание бюджета токенов, сбои API, прерывание пользователем, подтверждение прав доступа и др.
- Механизм Token budget и принятие решений об auto-continue гарантируют, что длительные задачи не прерываются из-за остановки модели

**Рекомендуемый приоритет**: ★★★★★ — ключ к пониманию работы всего продукта

---

### Глава 3: Система инструментов
**Файл**: [03-tool-system.md](03-tool-system.md)

**Ключевая идея**: Система инструментов — единственный канал между намерением LLM и реальным миром: не вспомогательный компонент, а основной инженерный актив.

**Ключевые находки**:
- Паттерн Self-Describing Tools: каждый инструмент объявляет свои возможности через `searchHint`, `prompt`, `userFacingSchema` и другие поля, позволяя модели динамически выбирать инструменты
- 40+ подкаталогов инструментов, все они диспетчеризуются через `toolExecution.ts` (1 745 строк)
- cc-notebook не анализировал эту систему отдельно — данная глава заполняет критический пробел

**Рекомендуемый приоритет**: ★★★★☆ — обязательно для разработчиков агентов

---

### Глава 4: Оркестрация агентов и многоагентная архитектура
**Файл**: [04-agent-orchestration.md](04-agent-orchestration.md)

**Ключевая идея**: Три нарастающих режима совместной работы (Subagent / Coordinator / Team Mode) используют один общий движок `runAgent()`, реализуя различное поведение через комбинацию параметров — одно из самых элегантных архитектурных решений.

**Ключевые находки**:
- 8 700 строк кода, 12 ключевых модулей — самая сложная подсистема всей архитектуры
- Team Mode использует протокол файлового почтового ящика (`teammateMailbox.ts`, 1 183 строки) для постоянного параллельного сотрудничества
- Coordinator Mode реализует полностью асинхронную коммуникацию через XML `<task-notification>` с изолированным AbortController

**Рекомендуемый приоритет**: ★★★★★ — образцовый пример проектирования многоагентных систем

### Глава 5: Prompt-инжиниринг
**Файл**: [05-prompt-engineering.md](05-prompt-engineering.md)

**Ключевая идея**: Prompt-инжиниринг — подсистема с наибольшей скрытой сложностью во всей системе: изменение одного `systemPromptSection` из 3 строк может одновременно повлиять на поведение модели, частоту попаданий в Prompt Cache, тарификацию токенов и согласованность между сессиями.

**Ключевые находки**:
- Системный промпт объёмом 8 000+ токенов — не «описание», а точное программирование поведения
- Многоуровневая стратегия Prompt Cache (`cacheScope: 'org'` / `'global'`) снижает стоимость токенов миллионов запросов на порядок
- Маркер `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` точно обозначает границу общего префикса, максимизируя глобальный Cache Hit

**Рекомендуемый приоритет**: ★★★★★ — обязательно для prompt-инженеров, образец коммерческого Prompt-дизайна

### Глава 6: Система Skill
**Файл**: [06-skill-system.md](06-skill-system.md)

**Ключевая идея**: Skill — это «СОП для ИИ»: накопленные рабочие процессы экспертов в формате Markdown наделяют ИИ воспроизводимыми профессиональными способностями.

**Ключевые находки**:
- Объединение декларативного и императивного стилей: Frontmatter объявляет метаданные (права, модель, условия срабатывания), тело содержит инструкции выполнения
- Многоисточниковая загрузка с приоритетным слиянием: bundled / пользовательский / проектный / Plugin / MCP уровни
- Механизм условной активации: автоматическое срабатывание по пути файла через frontmatter `paths`, поддержка динамического обнаружения

**Рекомендуемый приоритет**: ★★★★☆ — непосредственно применимо для проектирования Skill в Doramagic

### Глава 7: Система команд
**Файл**: [07-command-system.md](07-command-system.md)

**Ключевая идея**: Система команд реализует чёткое разделение ответственностей: команды отвечают за «запуск», инструменты — за «выполнение», LLM — за «принятие решений».

**Ключевые находки**:
- Три типа команд: PromptCommand (внедрение в диалог LLM), LocalCommand (локальное выполнение), LocalJSXCommand (с рендерингом UI)
- Ленивая загрузка: команды загружаются через `load(): Promise<Module>` отложенно, распределяя накладные расходы на первый вызов
- Два ключевых расширения классического паттерна GoF Command: ленивая загрузка + типизированные возвращаемые значения

**Рекомендуемый приоритет**: ★★☆☆☆ — применение стандартного паттерна проектирования, читать по необходимости

### Глава 8: Управление контекстом
**Файл**: [08-context-management.md](08-context-management.md)

**Ключевая идея**: Управление контекстом по своей сути является задачей сжатия информации — Claude Code разработал систему постепенной деградации от без потерь до с потерями, поддерживая непрерывность часовых сессий в окне 200K токенов.

**Ключевые находки**:
- Трёхуровневая стратегия сжатия: микросжатие (cache_edits, без потерь) → свёртка результатов инструментов (collapseReadSearch) → полное сжатие через Fork Agent (с потерями)
- 9 разделов промпта суммирования определяют неявную функцию искажения — какая информация наименее допускает потерю
- Инварианты безопасности: пары tool_use/tool_result нельзя разрывать, защита от рекурсии, механизм Circuit Breaker

**Рекомендуемый приоритет**: ★★★★☆ — ключевой справочник для разработчиков агентов с длительными сессиями

### Глава 9: Система памяти
**Файл**: [09-memory-system.md](09-memory-system.md)

**Ключевая идея**: Система памяти обеспечивает непрерывность Claude между сессиями — трёхчастное деление когнитивной науки (рабочая/эпизодическая/семантическая память) отображается на трёхуровневую архитектуру (окно контекста/Session Memory/Persistent Memory).

**Ключевые находки**:
- 5 700 строк кода реализуют полный жизненный цикл межсессионной памяти: извлечение, хранение, синхронизация, загрузка
- Синхронизация командной памяти (`teamMemorySync/`, 2 167 строк) — крупнейший отдельный модуль, поддерживающий сценарии многопользовательского сотрудничества
- `memdir/` реализует файлоподобную организацию памяти

**Рекомендуемый приоритет**: ★★★☆☆ — справочник для агентов, требующих долгосрочной памяти

### Глава 10: Модель безопасности и разграничения прав
**Файл**: [10-security-permission.md](10-security-permission.md)

**Ключевая идея**: Система безопасности — самая большая по объёму кода подсистема (~25 000 строк), реализующая 8-уровневую глубокую защиту: от AST-анализа до OS-песочницы, каждый уровень независим и используется совместно.

**Ключевые находки**:
- Уникальная модель угроз: сама языковая модель может быть введена в заблуждение через prompt injection для выполнения опасных операций
- Bash AST-парсер, реализованный на чистом TypeScript, понимает структуру команд (регулярные выражения не способны различить `echo "rm -rf /"` и `rm -rf /`)
- Двойная песочница: проверка прав на уровне приложения + изоляция на уровне ОС (macOS sandbox-exec / Linux bwrap) — даже при сбое прикладного уровня ОС подстрахует

**Рекомендуемый приоритет**: ★★★★★ — обязательно для инженеров по безопасности, эталон проектирования безопасности AI-агентов

## Словарь терминов

| Термин | Определение |
|--------|-------------|
| **Agentic Loop** | LLM в цикле чередует «рассуждение → вызов инструмента → ввод результата → снова рассуждение» до завершения задачи. Основной режим работы Claude Code. |
| **Async Generator Pipeline** | Сопрограмма TypeScript `async function*` — Query Engine использует её для оркестрации постепенного вывода потокового ответа. |
| **Auto-Continue** | Когда модель останавливается из-за лимита токенов (`end_turn`, но есть незавершённые вызовы инструментов), Query Engine автоматически вводит команду продолжения, не прерывая пользовательский опыт. |
| **Cache Editing** | Возможность Claude API редактировать кэш: удаление копий кэша старых сообщений без инвалидации всего кэша. Основа микросжатия. |
| **CLAUDE.md** | Файл инструкций на уровне пользователя/проекта, аналог `.editorconfig`, но ориентированный на ИИ. Вводится в системный промпт для управления поведением модели. |
| **Coordinator Mode** | Второй уровень оркестрации агентов: полностью асинхронная коммуникация, координация нескольких агентов через XML-уведомления, каждый с независимым AbortController. |
| **DCE (Dead Code Elimination)** | Удаление недостижимого кода на этапе компиляции. Вызовы `feature()` в bun:bundle полностью удаляют внутренние функции из внешних сборок. |
| **Defense in Depth** | Стратегия глубокой защиты. 8-уровневая система безопасности Claude Code: режим разрешений → сопоставление правил → AST-анализ → верификатор безопасности → проверка пути → классификатор → Hook → песочница. |
| **Fork Agent** | Независимый агент, запускаемый при полном сжатии контекста: читает полную историю диалога и генерирует структурированное резюме, не загрязняя текущую сессию. |
| **Frontmatter** | Блок YAML-метаданных в начале Markdown-файла (обёрнутый `---`). Skill-файлы используют его для объявления прав, модели, условий срабатывания и др. |
| **GrowthBook** | Рантайм-платформа Feature Flag, поддерживающая A/B-тестирование и поэтапный выпуск. Claude Code использует её для динамического управления переключателями функций и частотой сэмплирования. |
| **Ink** | TUI-фреймворк на основе React. Claude Code глубоко модифицировал его конвейер рендеринга (двойная буферизация, ANSI diff, аппаратная прокрутка). |
| **MCP (Model Context Protocol)** | Открытый протокол под руководством Anthropic, определяющий стандартизированную коммуникацию между AI-приложениями и внешними сервисами инструментов. Основан на JSON-RPC 2.0. |
| **Micro-Compaction (микросжатие)** | Стратегия первого уровня управления контекстом: через cache editing удаляются серверные копии кэша старых результатов инструментов, локально сохраняются заполнители. Без потерь. |
| **Overload Fallback** | При перегрузке основной модели (например, Opus) прозрачное переключение на запасную модель (например, Sonnet) — обязательно с предупреждением пользователю, никогда молча. |
| **Prompt Cache** | Механизм кэширования промптов Claude API. Запросы с одинаковым префиксом используют общий кэш, существенно снижая стоимость токенов. Доступны области `org` и `global`. |
| **REPL** | Read-Eval-Print Loop — основной режим взаимодействия Claude Code: чтение пользовательского ввода → обработка LLM → вывод результата → ожидание следующего раунда. |
| **Skill** | Определение рабочего процесса в формате Markdown, активируемое slash-командой или проактивным вызовом ИИ. По сути — «СОП для ИИ». |
| **Subagent** | Первый уровень оркестрации агентов: дочерний агент, выполняемый синхронно/асинхронно внутри главного процесса, общается через возвращаемые значения функций. |
| **System Reminder** | Системное сообщение, вводимое в историю диалога для динамического обновления контекстной информации модели (например, текущая дата, список доступных Skill). |
| **Team Mode** | Третий уровень оркестрации агентов: постоянное параллельное сотрудничество через протокол файлового почтового ящика, поддерживает три бэкенда: Tmux Pane / InProcess / Remote. |
| **Tool Result Storage** | Дисковое хранение результатов выполнения инструментов (`toolResultStorage.ts`) — после микросжатия результаты инструментов перемещаются из контекста сюда и восстанавливаются по необходимости. |
| **TUI (Terminal User Interface)** | Терминальный пользовательский интерфейс, интерактивный интерфейс Claude Code в чисто текстовом терминале на основе декларативного рендеринга React/Ink. |
