## プロジェクト背景

### ソースコードの出所

本レポートは2026-03-31に流出したClaude Code完全TypeScriptソースコードスナップショットに基づく。このスナップショットには512,664行のTypeScriptコード（`.ts` + `.tsx`）が含まれ、1,884個のファイルに分布し、35個のトップレベルディレクトリをカバーしている。ソースコードはminiサーバーの`~/Documents/openclaw/Doramagic/docs/research/claude-code-instructkr/src/`に保存されている。

### 分析方法論

**14サブエージェント並列分析**アーキテクチャを採用：5つのOpusエージェントが最も複雑なコアの章（アーキテクチャ概要、Query Engine、Agent編成、セキュリティモデル、コンテキスト管理）を担当し、9つのSonnetエージェントがその他の章を担当した。各エージェントはソースコードを独立して読み込み、アーキテクチャパターンを抽出し、競合他社分析の結論を検証し、最終的に総編集者が統一審査した。

この方法論自体が、Claude Codeのマルチエージェントアーキテクチャ（第4章）の実践的検証である——Claude CodeをClaude Codeで分析する。

### win4r/cc-notebookとの比較

win4r/cc-notebookは同じソースコードに対するコミュニティの分析ノートであり、本レポートは以下の次元で顕著な強化を行った：

- **独立したツールシステム章（第3章）**：cc-notebookはツールシステムを独立して分析していないが、本レポートがこの重要な空白を埋めた
- **ソースコードレベルの検証**：すべてのアーキテクチャ主張にファイル名、行番号、コードスニペットを添付し、二次転載ではない
- **理論的な根拠**：各章は学術理論の基礎（情報理論、キャッシュ理論、認知科学等）で始まり、工学的実装をより広い知識的枠組みに位置づけた

## 章別ガイド

### 第1章：アーキテクチャ概要と起動フロー
**ファイル**：[01-architecture-overview.md](01-architecture-overview.md)

**コアインサイト**：Claude CodeはReact/Inkベースのターミナルアプリで、BunをランタイムとしてREPLループでClaude APIを駆動しagentic開発タスクを実行する。

**主な発見**：
- 技術スタックの選択が的確：Bun + TypeScript + React/Ink + Zod v4 + OpenTelemetry、各選択に明確なエンジニアリング上の理由がある
- 512,664行のコードが1,884ファイル、35のトップレベルディレクトリに分布し、成熟した大規模エンジニアリングプロジェクト
- Feature Flagシステムは GrowthBook + bun:bundle デュアルトラック制を採用し、コンパイル時に内部機能を削除

**推奨優先度**：★★★★★ — 必読の出発点、グローバルなメンタルモデルを構築

---

### 第2章：Query Engine — LLMインタラクションのコア
**ファイル**：[02-query-engine.md](02-query-engine.md)

**コアインサイト**：Query EngineはClaude Codeの「鼓動」であり、7,400行のコード（わずか1.4%）でプロダクトの最重要パス——ユーザーとClaudeのすべてのインタラクション——を駆動する。

**主な発見**：
- コアアーキテクチャはAsync Generator Pipeline（コルーチンパイプライン）で、ストリーミングレスポンス、ツール呼び出し、コンテキスト圧縮、コスト追跡を一つのAsync Generatorで編成
- 少なくとも12種の異常分岐を処理：コンテキストウィンドウオーバーフロー、トークン予算枯渇、API障害、ユーザー中断、権限承認等
- Token予算とauto-continue決定機制で長タスクがモデルのstopで中断されないことを保証

**推奨優先度**：★★★★★ — プロダクト全体の動作を理解する鍵

---

### 第3章：ツールシステム
**ファイル**：[03-tool-system.md](03-tool-system.md)

**コアインサイト**：ツールシステムはLLMの意図と現実世界の間の唯一のチャネル——アクセサリーではなく、コアエンジニアリング資産。

**主な発見**：
- Self-Describing Tools（自己記述型ツール）パターン：各ツールは`searchHint`、`prompt`、`userFacingSchema`等のフィールドを通じて自身の能力を宣言し、モデルが動的に選択できるようにする
- 40+個のツールサブディレクトリ、すべて`toolExecution.ts`（1,745行）が一元的にスケジュール実行
- cc-notebookはこのシステムを独立して分析しておらず、本章が重要な空白を埋めた

**推奨優先度**：★★★★☆ — Agent開発者必読

---

### 第4章：Agent編成とマルチエージェントアーキテクチャ
**ファイル**：[04-agent-orchestration.md](04-agent-orchestration.md)

**コアインサイト**：3種の段階的な協調モード（Subagent / Coordinator / Team Mode）は同一の`runAgent()`コアエンジンを共有し、パラメータの組み合わせで異なる動作を実現——これが最もエレガントな設計上の意思決定。

**主な発見**：
- 8,700行のコード、12のコアモジュール、プロダクトアーキテクチャ中で最も複雑なサブシステム
- Team Modeはファイルメールボックスプロトコル（`teammateMailbox.ts`、1,183行）で永続化並列協働を実現
- Coordinator Modeは`<task-notification>` XMLで完全非同期通信を実現し、独立したAbortControllerによる隔離を持つ

**推奨優先度**：★★★★★ — マルチエージェントシステム設計の教科書的ケース

---

### 第5章：Promptエンジニアリング
**ファイル**：[05-prompt-engineering.md](05-prompt-engineering.md)

**コアインサイト**：Promptエンジニアリングはシステム全体で最も高い暗黙的複雑度を持つサブシステム——3行の`systemPromptSection`の調整が、モデルの動作、Cache命中率、token課金、クロスセッション一貫性に同時に影響する可能性がある。

**主な発見**：
- 8,000+ tokenのシステムプロンプトは「説明」ではなく、精確な行動プログラミング
- Prompt Cache分層戦略（`cacheScope: 'org'` / `'global'`）が数百万リクエストのtoken コストを一桁削減
- `SYSTEM_PROMPT_DYNAMIC_BOUNDARY`マーカーが共有プレフィックス境界を精確に画定し、グローバルキャッシュヒット率を最大化

**推奨優先度**：★★★★★ — Promptエンジニア必読、商業レベルのPrompt設計の手本

### 第6章：Skillシステム
**ファイル**：[06-skill-system.md](06-skill-system.md)

**コアインサイト**：Skillは「AIへのSOP」——人間の専門家のワークフローをMarkdown形式で蓄積し、AIに再現可能な専門実行能力を付与する。

**主な発見**：

- 多ソース読み込みと優先度マージ：bundled / ユーザーレベル / プロジェクトレベル / Pluginレベル / MCPソース
- 条件付きアクティベーション：`paths` frontmatterでファイルパスに基づき自動アクティベート、動的発見をサポート

**推奨優先度**：★★★★☆ — Doramagic Skill設計に直接参考価値あり

### 第7章：コマンドシステム
**ファイル**：[07-command-system.md](07-command-system.md)

**コアインサイト**：コマンドシステムは明確な関心の分離を体現——コマンドは「トリガー」を担当し、ツールは「実行」を担当し、LLMは「意思決定」を担当する。

**主な発見**：
- 3種のコマンドタイプ：PromptCommand（LLM会話に注入）、LocalCommand（ローカル実行）、LocalJSXCommand（UIレンダリング付き）
- 遅延読み込み設計：コマンドは`load(): Promise<Module>`で遅延読み込みし、起動コストを初回呼び出しに分散
- GoFコマンドパターンの2つの重要な拡張：遅延読み込み + 型付き戻り値

**推奨優先度**：★★☆☆☆ — 標準的なデザインパターンの適用、必要に応じて参照

---

### 第8章：コンテキスト管理
**ファイル**：[08-context-management.md](08-context-management.md)

**コアインサイト**：コンテキスト管理は本質的に情報圧縮問題——Claude Codeは可逆から非可逆への段階的デグレード体系を設計し、200Kトークンウィンドウ内で数時間のセッション継続性を維持する。

**主な発見**：
- 3層圧縮戦略：マイクロ圧縮（cache_edits、可逆）→ツール結果折りたたみ（collapseReadSearch）→フルFork Agent圧縮（非可逆）
- 圧縮用プロンプトの9つのセクションが暗黙の歪み度量関数を定義——どの情報が最も損失に耐えられないか
- 安全不変量：tool_use/tool_resultペアは切断不可、再帰保護、Circuit Breakerメカニズム

**推奨優先度**：★★★★☆ — 長セッションAgent開発の重要な参考

### 第9章：メモリシステム
**ファイル**：[09-memory-system.md](09-memory-system.md)

**コアインサイト**：メモリシステムによりClaudeはセッションを越えて継続性を保持——認知科学のワーキングメモリ/エピソードメモリ/意味記憶の三分法が、コンテキストウィンドウ/Session Memory/Persistent Memoryの三層アーキテクチャにマッピングされる。

**主な発見**：
- 5,700行のコードがクロスセッションメモリの完全なライフサイクルを実装：抽出、保存、同期、読み込み
- チームメモリ同期（`teamMemorySync/`、2,167行）が最大の単一モジュールで、マルチユーザー協働シナリオをサポート
- `memdir/`ディレクトリがファイルシステムライクのメモリ組織構造を実装

**推奨優先度**：★★★☆☆ — 長期メモリが必要なAgentに参考価値あり

### 第10章：セキュリティと権限モデル
**ファイル**：[10-security-permission.md](10-security-permission.md)

**コアインサイト**：セキュリティシステムはコード量最大のサブシステム（~25,000行）で、8層縦深防御を実装——AST解析からOSサンドボックスまで、各層が独立して使用可能で、層ごとに強化される。

**主な発見**：
- 独自の脅威モデル：AIモデル自体がprompt injectionにより危険な操作を実行させられる可能性がある
- 純TypeScript実装のBash ASTパーサーが、コマンド構造を理解するために使用（正規表現では`echo "rm -rf /"`と`rm -rf /`を区別できない）
- 二重サンドボックス：アプリケーション層の権限チェック + OS層の隔離（macOS sandbox-exec / Linux bwrap）、アプリケーション層に誤りがあってもOSが保護

**推奨優先度**：★★★★★ — セキュリティエンジニア必読、AI Agentセキュリティ設計の標準

---

### 第11章：MCP統合
**ファイル**：[11-mcp-integration.md](11-mcp-integration.md)

**コアインサイト**：Claude CodeはピュアなMCPクライアントで、12,310行のコードが完全な接続管理、OAuth認証、ツール発見と動的登録を実装している。

**主な発見**：
- MCPツールは`mcp__<serverName>__<toolName>`形式で動的に登録され、内蔵ツールと同じ実行フレームワークを共有
- OAuth 2.0認証にXAA（Cross-Application Access）クロスアプリケーションアクセスサポートを含む
- stdio/SSE/HTTP Streamable/WebSocketの4種のトランスポート層をサポート

**推奨優先度**：★★★☆☆ — MCPエコシステム開発者必読

---

### 第12章：ターミナルUIとレンダリングエンジン
**ファイル**：[12-terminal-ui.md](12-terminal-ui.md)

**コアインサイト**：Claude CodeはReact/Inkフレームワークを深くカスタマイズ——ダブルバッファレンダリング、ANSI diffエンジン、ハードウェアスクロール加速、IME対応カーソル配置、純テキストターミナルでGUIに近いインタラクション体験を実現。

**主な発見**：
- レンダリングパイプラインのフレーム間隔`FRAME_INTERVAL_MS = 16`（理論上62.5fps）、モニターのリフレッシュレートに合わせる
- 完全なVimモード実装：独立した状態機、NORMAL/INSERT二モード、operators/motions/textObjects全集をカバー
- カスタムInkレンダラー（`src/ink/`）がネイティブInkのレンダリングパイプラインを置き換える

**推奨優先度**：★★☆☆☆ — TUIフレームワーク開発者の深い参考、他の読者はスキップ可

### 第13章：モデル選択とコスト制御
**ファイル**：[13-model-cost.md](13-model-cost.md)

**コアインサイト**：3つの設計哲学——ユーザー意図優先（多層オーバーライドチェーン）、コスト完全透明（費用の強制表示）、サイレントダウングレードなし（Overload Fallbackは必ず警告）。

**主な発見**：
- モデル選択優先度チェーン：`/model`コマンド → `--model`フラグ → 環境変数 → 設定ファイル、上位が下位をオーバーライド
- 組み込みの精確な価格表（`modelCost.ts`）、モデル別リアルタイムコスト追跡をサポート
- OpusからSonnetへのOverload Fallbackはサイレント切り替えを絶対に行わず、ユーザーへの警告表示が必須

**推奨優先度**：★★★☆☆ — マルチモデルシステムルーティング設計の実用的参考

### 第14章：Feature Flagsと可観測性
**ファイル**：[14-feature-flags-observability.md](14-feature-flags-observability.md)

**コアインサイト**：デュアルトラックFeature Flag（コンパイル時 bun:bundle DCE + 実行時 GrowthBook）とOpenTelemetryの三大柱を組み合わせ、コンパイル削減から実行追跡までの全チェーン可観測体系を構築。

**主な発見**：
- コンパイル時フラグはDead Code Eliminationを通じて内部コードを完全削除し、リバースエンジニアリングを防止
- デュアルAnalytics：Datadog（外部監視）+ 1Pイベントログ（内部BigQuery）、イベント名プレフィックス`tengu_*`
- プライバシー優先設計：デフォルトでコード内容やファイルパスを記録しない

**推奨優先度**：★★☆☆☆ — 大規模SaaS可観測性設計の参考

## 用語集

| 用語 | 定義 |
|------|------|
| **Agentic Loop** | LLMがループ内で「推論→ツール呼び出し→結果注入→再推論」を交互に実行し、タスクが完了するまで続く。Claude Codeのコア動作モード。 |
| **Async Generator Pipeline** | TypeScriptの`async function*`コルーチン。Query Engineがストリーミングレスポンスの逐次出力を編成するために使用。 |
| **Auto-Continue** | モデルがトークン制限により停止した際（`end_turn`だが未完了のツール呼び出しがある）、Query Engineが自動的に継続命令を注入し、ユーザー体験を中断しない。 |
| **Cache Editing** | Claude APIのキャッシュ編集機能。キャッシュ全体を無効化せずに古いメッセージのキャッシュコピーを削除できる。マイクロ圧縮の基盤。 |
| **CLAUDE.md** | ユーザー/プロジェクトレベルの命令ファイル、`.editorconfig`に類似するがAI向け。システムプロンプトに注入されモデルの動作を誘導する。 |
| **Coordinator Mode** | Agent編成の第二層モード：完全非同期通信、XML通知で複数Agentを調整、各自が独立したAbortControllerを持つ。 |
| **DCE (Dead Code Elimination)** | コンパイル時に到達不可能なコードを除去。bun:bundleの`feature()`呼び出しにより内部機能が外部ビルドから完全に削除される。 |
| **Defense in Depth** | 縦深防御戦略。Claude Codeの8層セキュリティ体系：権限モード→ルールマッチング→AST解析→セキュリティ検証器→パス検証→分類器→Hook→サンドボックス。 |
| **Fork Agent** | コンテキストのフル圧縮時に起動される独立Agent。完全な会話履歴を読んで構造化サマリーを生成し、現在のセッションを汚染しない。 |
| **Frontmatter** | Markdownファイルのヘッダー部分のYAMLメタデータブロック（`---`で囲まれる）。Skillファイルが権限、モデル、トリガー条件等を宣言するために使用。 |
| **GrowthBook** | 実行時Feature Flagプラットフォーム。A/Bテストとグレーリリースをサポート。Claude Codeが機能スイッチとサンプリングレートを動的に制御するために使用。 |
| **Ink** | ReactベースのターミナルUIフレームワーク。Claude Codeはそのレンダリングパイプラインを深くカスタマイズ（ダブルバッファ、ANSI diff、ハードウェアスクロール）。 |
| **MCP (Model Context Protocol)** | Anthropicが主導するオープンプロトコル。AIアプリと外部ツールサービスの標準化通信を定義。JSON-RPC 2.0ベース。 |
| **Micro-Compaction（マイクロ圧縮）** | コンテキスト管理の第一段戦略：Cache editingで古いツール結果のサーバーサイドキャッシュを削除し、ローカルにプレースホルダーを保持。可逆。 |
| **Overload Fallback** | プライマリモデル（Opus等）が過負荷の際に透明的にセカンダリモデル（Sonnet等）にダウングレード。必ずユーザーへの警告表示が必要で、サイレント切り替えは絶対禁止。 |
| **Prompt Cache** | Claude APIのプロンプトキャッシュ機構。同一プレフィックスのリクエストがキャッシュを共有し、tokenコストを大幅に削減。`org`と`global`の2つのスコープがある。 |
| **REPL** | Read-Eval-Print Loop。Claude Codeのコアインタラクションモード：ユーザー入力を読み取る→LLM処理→結果出力→次のラウンドを待つ。 |
| **Skill** | Markdown形式のワークフロー定義。スラッシュコマンドまたはAIによる主動的な呼び出しでトリガー。本質的に「AIへのSOP」。 |
| **Subagent** | Agent編成の第一層モード：メインプロセス内で同期/非同期実行されるサブAgent、関数の戻り値で通信。 |
| **System Reminder** | 会話履歴に注入されるシステムレベルのメッセージ。モデルのコンテキスト情報を動的に更新するために使用（現在の日付、利用可能なSkillリスト等）。 |
| **Team Mode** | Agent編成の第三層モード：ファイルメールボックスプロトコルで永続化並列協働を実現、Tmux Pane / InProcess / Remoteの3種のバックエンドをサポート。 |
| **Tool Result Storage** | ツール実行結果のディスクコールドストレージ（`toolResultStorage.ts`）。マイクロ圧縮後のツール結果がコンテキストから移動し、必要に応じて復元。 |
| **TUI (Terminal User Interface)** | ターミナルユーザーインターフェース。Claude Codeが純テキストターミナルで実現したインタラクティブなインターフェース、React/Inkの宣言的レンダリングベース。 |
